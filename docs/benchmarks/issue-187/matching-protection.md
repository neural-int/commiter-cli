# PR #188: CPU履歴照合の保護（P2のみ）

基点: `686acde8`。確認日: 2026-11-03。

## 変更

通常Collectは取得後のCPU照合にも親contextを渡す。出典の重複検査、属性投影、比較、候補の包含検索、split/mergeの組み合わせ探索で停止を確認する。停止時は未完成の照合結果を成功として返さない。

照合段階でも既存のmemoryGuardを動作させる。500msの監視、RSS 1.5GiBでの一時停止、正常サンプル2回による再開、RSS 2GiB・critical pressure・監視不能・30秒のメモリ停滞による停止を維持する。これらはサンプリングによる保護であり、瞬間的なピークを完全に制限する保証ではない。親キャンセルは待機中にも反映する。

split/mergeでは、変更方向と内容の包含関係で候補を絞り、最初の包含位置を一度だけ計算してから異なるパスの非重複ペアを調べる。無関係な全履歴同士の組み合わせを先に列挙しない。同一パス、EOF、曖昧性、先頭の一致範囲だけを使う規則は維持する。すべての断片が候補になる場合の最悪計算量が常に線形になるとは主張しない。

順序付きの書換え履歴も、現在の変更の旧側に一致する先行候補と、新側に一致する後続候補を先に選ぶ。その後に同じTurn・項目順・中間内容の一致を確認する。現在の変更に対応しない全履歴のペアを先に走査しない。

RPCの30秒無応答検知、少量のデータを送り続けるストリームの許容、その他のP3の動作は変更しない。新しい依存・生成要求・自動リトライも追加しない。

## 検証

回帰テストでは実際のチェックポイントで停止を発生させ、属性投影・比較・split/merge・包含検索中のキャンセル、メモリ上限による打ち切り、一時停止からの再開とキャンセルを確認する。Collectが照合時のメモリ保護を通らずに成功結果を返さないことも検査する。実機をメモリ上限まで圧迫する試験ではなく、既存の注入可能なメモリサンプルを利用する。

一時的なGo overlayを用い、基点HEADのcompareとmarkSplitMergeEvidenceを参照関数として最終実装と比較した。固定シード188・300ケース・選択3パス・履歴30操作で、追加・削除・書換え・不正diff・partial履歴を組み合わせ、Comparison全体が一致した。参照コードは一時検証用で製品には含めない。最初の一時コードの未使用importを除去してから実行した。既存のrename・split/merge・EOF等の回帰テストも維持する。

既存の固定合成benchmarkを変更せず、各規模1回実行した。モデル・実履歴は使用していない。
