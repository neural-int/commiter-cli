C02のprefix cache標本最大は2.249GiB、active＋cache標本最大は6.521GiB。最後のclear後はcache 0だった。ピークactiveは基準と同じでも、保持バッファ全体が同じという意味ではない。OS全体のswap使用は約1.793GiB増えたが、他プロセスや既存の圧縮・swap状態も含むため、この変更だけが原因とは断定しない。今回の観測は局所的短縮を示す一方、メモリ保持の増分と安定した全体効果を判断するには不足している。

同期的evalを残しているため、CPU/GPU並列化の検証ではない。同期とclearを同時に減らした変更であり、両者それぞれの因果効果は分離していない。明示同期/clearの直接時間だけでは、後続の再確保コストを説明できない。

前標準はcacheMemoryの時系列がなく、保持量の増分は定量比較できない。今回のactive+cache最大はchunk境界の標本最大で、Memory.peakMemoryはactiveのみ。RSSは別指標でありMLX値と加算しない。OS計測はGPUフレーム受信後で厳密同時ではなく、観測負荷も増えている。
