## Objective
 - Userより指定されたGitHub上のissueの課題を解決する。

## Success Criteria
**Verification**をすべて達成した場合のみ以下の最終品質ゲートを実行する。**これらが満たされた場合Goalを完了とする。**
 - [ ] test, lint, build など各種チェックを実行し全てpass
 - [ ] 機能の更新・削除による不要なテストケースは整理されているか
 - [ ] 自明なテストケースを増やしていないか

## Verification
 - [ ] issueの完了条件をすべて達成しているか
 - [ ] isuueのチェックボックスにすべてチェックが入っているか？

## Constraints
 - mainまたはmasterブランチを汚さない。Iteration専用のworktreeで実行。
 - **Iteration Policy**に従い進めること
 - benchmarkなどの計測結果を改竄しない
 - 可能な限りリポジトリの開発の趣旨・方向性・思想に沿った課題解決を提案・実行すること。
 - 実行中はagent skillsを使用しない

 ### Japanese Writing Guidelines
   報告は日本語で記述し、以下を守る。
    - 結論→根拠の順に書く。
    - 一つの段落では一つの話題を扱う。事実・推定・未確認事項を区別し、未確認の内容を断定しない。
    - 主語・対象・条件を明確にする。原因を述べるときは、なぜその結果になるのかを説明する。
    - 翻訳調の比喩、擬人化、俗語を避け、具体的な状態や処理を書く。「情報を運ぶ」「データが語る」「効く」「筋がいい」などで説明を済ませない。
    - 中身のない前置きや強調、同じ主張の言い換えを避ける。
    - 判断に必要な根拠・条件・識別子は残し、不要な作業経過や装飾を削る。短文化のために必要な説明を省かない。

## Iteration Policy
以下の**WorkFlow**に従うこと。

 1. 調査・検証
 isuue課題を解決するための仮説をもとに調査・検証。
  - 2回目以降の仮説・検証内容はNext Stepsに従う。
  - まず課題に対するアプローチの方向性が適切か、検証が必要かどうかを判断する。
  - 必要に応じて外部ネットワークを使用し調査。issueの履歴も必要に応じて参照。
  - 検証が必要な場合、立証可能になる最小限の回数で検証。

 2. 報告
  該当issueのスレッドへ以下のフォーマットに従い新規コメントを追加。
  **Constraints.Japanese Writing Guidelines** のルールに則って記述。
    ## 要約
    - 検証結果と考察の要約を人間向けにわかりやすく噛み砕いて簡潔に整理。
    ## 検証結果
    - 検証から得られた観測的事実・結果のみを整理。
    ## 考察
    - 検証結果から得られた事実をもとに客観的考察を詳細に記述。
    ## Next Steps
    - 考察からisuueの課題解決に向けた次のActionを箇条書きで記述。(Action + なぜそのActionなのか)のセットで根拠を明確にする。

 3. 判断
  作業履歴をcommit&pushし、iterationを継続or終了するかを判断する。
  - **Success Criteria**全条件を満たしている場合goal達成として終了する。
  - **Blocked Condition**を一つでも満たした場合、Blockedとして停止。
  - 上記に該当しない場合は**4.継続**へ進む

 4. 継続
 **2.報告**で作成した新規コメントへのリンクを以下のフォーマットで、該当issue本文内に目次セクションを作成｜更新。
    ### 見出し[コメントへのlink]
       - 内容一文。
 完了後**1.検証** に戻る。


## Blocked Condition
 以下の場合、**WorkFlow**を継続せず、停止する。
 -  **WorkFlow**のiteration回数を増やしても作業・検証・改善による効果が極端に少ないことが見込まれる。またはこれ以上の解決や改善は望めない（天井値）。
 -  isuueで定義されている課題を解決するために、issueのスコープを逸脱する可能性がある。
 -  要件同士が矛盾している。
 -  isuue上に完了条件が定義されていない。
 -  合理的な進め方をするために必要な入力が不足している。
