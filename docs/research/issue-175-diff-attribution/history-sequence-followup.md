# 保存履歴候補の内容確認（Git照合なし）

## Goal

候補の依頼・編集列・最終応答を読み、実在する作業の途中経過として解釈できるかを確認。現在のGit差分は取得せず、LLMや本番Plannerは呼ばない。

## 確認例1：同じ依頼内の6段階

依頼の要旨はMinistral公式tokenizer/chat template/Thinking/EOSの扱いを整備し、前回条件で再測定すること。最終応答は公式tokenizerを使用した再測定完了と報告・ログ公開の説明。

同じ報告書にadd1回とupdate5回が保存され、APIのitem順で次の経過を読めた。

1. 再検証報告書を作成。実行中の状態を記載。
2. Reasoning C01の3phase完了とvalidator受理を追記。
3. Reasoning C02のGrouping結果と後段実行中の状態を追記。
4. 4ケース完了に合わせて要約・結果を更新。
5. 暫定見出しを解消し、検証時に判明したrunner挙動の説明を追記。
6. 公開用のログ・要求応答・監査記録等への案内を追記。

最初のaddはファイル内容として保存され、後続updateは差分として残る。依頼と最終応答だけでなく中間編集を確認できた。途中の報告内容の正確さや実行の成否を履歴だけで独立検証したわけではない。

## 確認例2：2つの依頼にまたがる4回の編集

先の依頼はIssueへ報告書をコメントすること。対応する編集は報告書の投稿状況更新、最終応答は投稿済み・commit/push未実施の説明。

後の依頼は検証ログ・成果物を対応ブランチへpushすること。同じ報告書に保存/公開状況と成果物一覧の更新が3回残り、最終応答はcommit/pushとログ収録の説明。依頼の追加によって同じファイルが再編集される実例として読める。

両区間ともitemの全ページを読み終えており、依頼textとfinal_answerを確認。ただしthread全体は4MiB受信枠で途中停止。同一ファイル・同一threadという理由だけで同じ変更目的とは判断しない。

## Limits / Corrections

調査用入力の抜粋は最大8KiBとし、commandExecutionの本文/出力は使用せず、秘密形式・ホームpath・メール形式を除去した。抜粋はローカル<PRIVATE_TMP>/issue175-sequence-detail.logに保持し、報告書には依頼/応答の要旨だけを記録。

addのdiffは生ファイル内容で、Markdownの先頭マイナスを削除記録として数えると誤る点を修正。updateの追加行/削除行の全体一致は多hunkの部分編集に適さず、その一致0件から連続性なしとは結論しない。

全中間状態を復元するpatch replayはまだ実施していない。最初のadd＋後続updateが取得できた例は復元検証の有力候補だが、改行/行位置/省略/間に挟まるshell編集などの完全性は未確認。取消しを確証できた例も今回なし。

取得は5秒/4MiB枠内で約3.31秒、部分標本。目的は候補の内容確認までで、Gitとの帰属精度評価、履歴全文の公開、Adapter設計、Hooks導入は行わない。
